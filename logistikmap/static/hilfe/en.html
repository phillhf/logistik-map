Overview: what Logistik Map does

Logistik Map models how goods move through a hospital: from the truck dock through stores, corridors, lifts and stairs to the wards and back. You enter where goods can move, who moves them and what is delivered when. The program then simulates a whole day. It shows where transports have to wait, which lift is overloaded at what time and how many vehicles or staff you need.

The basic idea in four steps

  1. Plans and paths: You upload the floor plans as PDF and draw every path on which goods can move, usually the corridors. This is not a fixed route. You only tell the system where it may go.
  2. Points: On the paths you place points: gates at the dock, the store, the kitchen, wards, lifts and stairs.
  3. Master data: You define how fast the transport service or an AGV moves, how many there are, how much fits into a lift and how long it takes per floor.
  4. Deliveries: You enter what happens, e.g. “At 8:00, 5 pallets from Gate 1 to ward B25”. The system finds the route, the lift and the transport type itself.

Afterwards the Timeline shows all trips as moving dots on the map. The Analysis shows waiting times, bottlenecks and utilisation. With Scenarios you try out changes (“What if lift West is out of service?”) without touching the real data.

Tip: The Getting started page keeps checking what is still missing. Every open item has a link straight to the right place. If you are stuck, look there first.

General use

Header and menu

  • Hospital selection (next to “Logistik Map”): switch between hospitals. Administrators also find ＋ New hospital … here. See Several hospitals.
  • Menu items in working order: Getting started · Buildings & plans · Map · Master data · Deliveries · Analysis · Scenarios · Users · Settings · Help. You only see the pages your role allows.
  • ? opens the help for exactly the page you are on.
  • On a phone the menu items are behind the ☰ button at the top left. Wide tables can be swiped sideways.
  • Update available: when there is a new version, administrators see a yellow item “⬆ Update … available” in the menu (on a phone with a badge on ☰). Tapping it leads straight to Settings → Updates.
  • Your name (right) opens a menu: language, change password, sign out. Hovering shows user name, role and installed version.

Forms, saving and confirmations

  • Most fields have a short grey explanation underneath. This help explains the same fields in more detail.
  • Required fields cannot be saved empty. If there is an error, the message appears at the top of the dialog and your input is kept.
  • Logistik Map never changes the network without your consent. Wherever the system would connect or delete something, it asks first with Yes or No.
  • Confirmations and errors appear at the bottom right. Error messages carry a code you can pass on to IT.

Several people at the same time

Several people can work at the same time. If someone changes the floor you are editing, the map reloads and tells you who changed it. Every change is recorded with time and user in the audit log.

After an update

When Logistik Map is updated, the open page reloads by itself once it notices the new version (within a minute or when you return to the browser tab). If you still see the old interface, press Ctrl + F5 once.

Several hospitals

One installation can manage several hospitals. Each hospital is completely separate: its own building sections, plans, paths, master data (transport types, cart types, lifts), deliveries, scenarios, special days, federal state and analyses. Only users, roles and sign-in are shared.

Adding a new hospital

  1. Choose ＋ New hospital … in the selection next to “Logistik Map” (or under Settings → Hospitals).
  2. Name: e.g. “North Hospital”.
  3. Copy transport types and cart types from: either copy the values of an existing hospital or start with the default values. Buildings, plans, lifts and deliveries always start empty.
  4. Create and switch. Then “Getting started” guides you through setting up the new hospital, beginning with the federal state.

Switching, renaming, deleting

  • Switch: choose the hospital in the selection at the top. The choice applies to your browser; other users stay in theirs.
  • Rename and delete: under Settings → Hospitals. Deleting removes everything of that hospital and can only be undone from a backup. The last remaining hospital cannot be deleted.

Uploading and assigning PDF plans

  1. Under Uploaded PDF plans click Upload PDF or drag files onto the area. You can choose several PDFs at once. Each file gets a row with progress and result.
  2. At a floor click Assign plan, choose the PDF and, for multi-page PDFs, the page.
  3. The plan is converted into map tiles once. The status shows waiting, being prepared … %, ready or error. Large plans take a few minutes; you can keep working meanwhile.
  • Large files: PDFs are transferred in 8 MB pieces, even plans over 100 MB. If an upload still fails, a proxy or filter in the network is usually the cause. Then upload the PDF in a browser directly on the server.
  • Prepare again: creates the tiles once more, e.g. after an error.
  • Change plan: for a new plan version, assign the new PDF. If paths and points are already drawn on the floor and the new plan is shifted or has a different scale, realign them with the Align tool. Logistik Map offers this right away.
  • Remove plan: only removes the assignment. The PDF stays in the list.
  • The column used shows how often a PDF is assigned to a floor. A PDF can only be deleted once it is no longer used anywhere.
Data protection: The plans stay on your server in the data folder. They are not sent anywhere.

Moving and zooming

  • Zoom: mouse wheel or the + and − buttons at the top left.
  • Move: drag with the left mouse button. While drawing with a tool, drag with the right (or middle) mouse button so that no click accidentally adds a corner.
  • Measure distance: click points, the length is shown. Double-click or Esc ends measuring. This is also how you check the scale.
  • The scale bar at the bottom left shows a length in metres.

Scale

Without a scale the system does not know how long a path is in metres and cannot calculate travel times. Every floor needs its own scale because plans may be printed differently.

Option 1: type it in (recommended if the scale is printed on the plan). At the top of the map there is the field Scale 1 :. Enter the number from the title block, i.e. for “1:200” enter 200, and press Save. If Logistik Map finds the scale in the PDF text, it is already suggested in the field (“Read on the plan: 1:200”). Then just save.

Option 2: measure. In Edit mode choose Set scale → Measure on the plan. Click two points whose distance you know, e.g. the ends of a dimensioned wall, and enter the distance in metres. The further apart the points, the more accurate.

Careful with “1:N”: The calculation from the title block is only correct if the PDF was saved at its original paper size. If the plan was scaled down when the PDF was created (e.g. A0 to A3), “1:200” no longer holds. So check the scale after saving with Measure distance on a known length. If it differs, use option 2.

Editing the map: paths, points and rooms

In Edit mode the toolbar appears. Clicking a tool turns it on; clicking the same button again switches back to Select. A short hint at the bottom of the map always says what the active tool expects.

The principle: paths instead of fixed routes

You do not draw every single delivery route. You draw once every path on which goods can move, a network like a road network. For each delivery the system finds the fastest route in it. Example: three docks, a goods-in area and a store. You draw the corridor from the docks to goods-in and on into the store and place the three gates, goods-in and the store as points on it. You do not need connections “from every point to every other”.

Rooms do not matter for route finding. They are only for orientation. What counts are paths and points.

Drawing paths properly

  • Draw along the middle of the corridor and click at every corner and every branch.
  • Junctions: if you draw across an existing path, a junction is created automatically at the intersection. Starting or ending on a path also connects. So you do not have to draw junctions in one go.
  • If you click near an existing point (about 20 screen pixels), the line snaps to it.
  • Almost horizontal or vertical pieces are straightened.
  • Open ends are marked orange: the path does not continue there. If that is intended (dead end), leave it. Otherwise drag the end in “Select” onto the point it should connect to.
  • Simply draw through doors, airlocks and fire doors. If a door is a bottleneck (only one trolley at a time), enter that on the path segment, see below.

Lifts and stairs across several floors

  1. On the first floor use Add point to place the lift directly on the corridor in front of the lift door, type “Lift/stairs”, then + new lift and give it a name (e.g. “Lift West”).
  2. On every other floor where it stops, add another “Lift/stairs” point and choose the same “Lift West” in the list.
  3. Enter spaces and times under Master data → Lifts and stairs.

All points with the same lift are connected automatically. The travel time follows from the difference of the levels. Stairs work the same way but may only be used by transport types with “Can use stairs” ticked.

“Getting started” reports a lift drawn on only one floor and floors not connected to the rest of the network.

Connections between building sections

For bridges, link corridors or ramps between houses: place a “Connection” point on both sides, each on the path. Then at one of them use Add connection, choose the point on the other side and enter the path length in metres. The connection works in both directions.

Check gaps

Small gaps easily happen while drawing: one corridor ends half a metre next to another, or a point lies beside the path. The ⇢ Check gaps button shows the number of such places. A click goes through them one by one: the map jumps to the spot, shows the suggestion dashed and asks:

  • Yes, connect: the two ends, or the point and the path, are connected.
  • No: everything stays as it is and this place is never reported again. Right for intended dead ends or two corridors that are not connected (e.g. separated by a wall).
  • End check: stop. The remaining places stay open.

Logistik Map never connects anything without your “Yes”.

Aligning after a plan change

If a new plan version is shifted, rotated or scaled differently, the drawn paths no longer fit. To realign them:

  1. Choose the Align tool.
  2. Click a drawn point or a room corner (old position).
  3. Click the spot on the new plan where this point belongs (new position).
  4. Repeat for at least 2, better 3 pairs, as far apart as possible (e.g. three building corners).
  5. Apply. All elements are moved, rotated and scaled; the scale adjusts.

Master data

Master data is the basis of all calculations. Example values are entered. Check and adapt them to your hospital, otherwise the analysis calculates with assumptions. Each hospital has its own master data.

Transport types

A transport type describes who or what transports. Typical are “Transport service” (people pushing trolleys) and “AGV” (automated guided vehicles).

FieldMeaning and typical values
NameHow the transport type appears in deliveries and analyses.
ColourColour of the trips in the timeline and in charts.
Speed (m/s)Average speed on the paths. Pushing a trolley: about 0.8–1.2 m/s, AGVs often 0.5–1.0 m/s. 1 m/s = 3.6 km/h, a slow walk.
Loading time at start (seconds)How long loading or picking up the trolleys at the start takes, per trip.
Unloading time at destination (seconds)How long parking and handing over at the destination takes, per trip. Also applies at the return destination for a loaded return trip.
Trolleys per tripHow many trolleys a person or vehicle moves at once. With 1, 6 linen trolleys become 6 trips; with 2, 3 trips.
Number of vehicles / staffHow many people or vehicles are on duty at the same time. For the transport service, the number of staff driving transports at the same time; for AGVs, the number of vehicles. This means people on duty, not positions: add breaks, holidays and sickness yourself. Each trip occupies one person or vehicle from departure until return. If all are busy, the next trip waits. 0 = unlimited. Then nobody ever waits for staff and missing staff never shows up as a bottleneck.
Reserves the lift exclusivelyFor AGVs: the vehicle travels alone in the car, people have to leave. The lift's clearing time is added. Not ticked: the trip shares the car with other trolleys as long as there is space.

ShiftsOptional. Each row is a shift with time from–to, number and weekdays, e.g. “Mon–Fri 06:00–14:00, 3 people”. If shifts are entered, their number applies instead of the fixed number above. Outside all shifts nobody is available; trips wait until the next shift starts. Overlapping shifts add up.

Lifts and stairs

On the map you place lifts as points at every stop. Their properties are set here.

FieldMeaning and typical values
Namee.g. “Lift West” or “Bed lift 3”.
TypeLift or stairs. For stairs only the time per floor counts.
SpacesHow many standard trolleys fit into the car at once (1 space = 1 linen trolley). A pallet needing 2 spaces takes the whole car of a 2-space lift. 0 = unlimited.
Travel time per floor (seconds)Pure travel time for one floor, typically 3–10 s. For stairs: time for one floor on foot with a load, about 20–40 s.
Door time (seconds)Opening, getting in or out and closing. Counted twice (in and out), typically 8–15 s.
Average wait for the car (seconds)Until the car arrives after calling, including passenger traffic. If the car is already on the floor, this time is skipped. Typically 20–60 s.
Clearing time for AGVs (seconds)Extra time until people have left when an AGV reserves the lift.
Only for these transport typesNothing ticked = everyone may use the lift. If some are ticked, only those may. Use this for a bed-only lift or an AGV lift.
Base load by peopleTime windows with a percentage, e.g. “Mon–Fri 07:00–09:00, 40 %”. Means: in this period the lift is busy with staff, patients and visitors 40 % of the time. These passenger trips block the car, so goods wait longer. Passenger trips themselves do not count as waiting time.

How the system calculates a lift trip:

Duration = average wait for the car + 2 × door time + floors × travel time per floor (+ clearing time for AGVs)

Example: 30 s wait + 2 × 10 s door + 3 floors × 8 s = 74 seconds. With an AGV and 20 s clearing time: 94 seconds.

Do not count twice: “Average wait for the car” and “Base load” both model passenger traffic. If you enter a base load, set the average wait rather small (e.g. 10 s), otherwise passenger traffic counts twice.

Deliveries and transports

A delivery describes a recurring transport: what (load), when (time and days), from where to where and what happens afterwards (return trip). This covers external deliveries (trucks), supply of the wards, disposal and internal transports such as bed exchange.

New delivery in one line

At the top of the page there is a sentence to fill in:

At [08:00] , [5] [pallets] from [Gate 1] to [B25], then [return empty] → Add

The system finds the route, the lift and the transport type itself. The name becomes “Gate 1 → B25” automatically. After adding, a message confirms it, e.g. “uses transport service, approx. 6 min route”. If there is no route yet, the message says so and “Getting started” shows the cause. Everything else (days, period, deadline …) you change afterwards in the list with Edit.

The choice after “then”:

  • return empty: the person or vehicle returns empty to the start (default).
  • return loaded: something is carried back again, e.g. soiled bed there, clean bed back.
  • stays there / truck leaves: no return trip, e.g. for external suppliers.

How Logistik Map calculates

This chapter explains what happens behind timeline and analysis, so you can judge the results and adjust master data in a targeted way.

Deliveries become trips

For the chosen day the system takes all active deliveries that take place on that day. Each delivery becomes trips: number of trolleys divided by “trolleys per trip”, rounded up. 7 linen trolleys at 2 per trip become 4 trips. All trips of a delivery start at the same time, i.e. one after another if staff is limited.

Deliveries from the previous day that run past midnight are included, so that staff and lifts are not artificially free in the morning.

Route finding

For every trip the system finds the fastest route through the network, measured in time, not metres. It counts:

  • the length of each path segment (from plan and scale or the entered value) divided by the speed of the transport type,
  • lift trips with waiting, door and travel time, stairs with their time per floor,
  • connections with their entered length.

Excluded are path segments blocked for the transport type, lifts it may not use and stairs if “Can use stairs” is not ticked. With via points the route must pass them. Waiting times do not influence route choice: the system does not switch to another lift by itself if one is full. Model that with via points or scenarios.

Course of a trip

  1. Request a vehicle or person: at the time of the delivery. If nobody is free (number or shift exhausted), the trip waits. This counts as waiting for vehicle.
  2. Loading at the start: loading time of the transport type. If the start point has “At most at the same time”, the trip waits for a free place.
  3. Driving: segment by segment. At bottlenecks it waits until there is room (at bottleneck).
  4. Lift: the trip joins the queue (at lift), see below.
  5. Unloading at the destination: unloading time, possibly waiting for a free place.
  6. Return trip as set. Only then is the person or vehicle free again.

How the lift is calculated

  • Every lift is one car. Waiting trips board in order of arrival.
  • Trips with the same start and destination floor travel together as long as there is space. A linen trolley (1 space) and a roll container (1 space) fit together into a car with 2 spaces.
  • Transport types with “Reserves the lift exclusively” (AGV) always travel alone and need the clearing time on top.
  • If the car is already on the right floor, the average wait for the car is skipped.
  • Base load: in the entered time window, passenger trips occupy the car for the given share of time.

Truck at the gate

If a delivery starts at a point of type “Gate / dock (truck)”:

  1. The truck arrives at the given time and waits until one of the gates is free (“At most at the same time”, empty = 1).
  2. It occupies the gate for units × minutes per unit: 10 pallets × 2 minutes = 20 minutes.
  3. Only then do the trips into the building start, which need staff, lifts and paths as usual.

If 4 trucks arrive at the same time at a gate with “1”, the second is unloaded after the first, the third after the second and so on. The analysis then shows the gate as a bottleneck with waiting time.

The model is deliberately coarse. It does not know oncoming traffic in corridors, breaks within a shift or people switching to other lifts. It is good for finding bottlenecks and comparing variants. The absolute minutes are guide values; the better the master data, the closer to reality.

Analysis

The analysis calculates all deliveries of a day. At the top choose the view (Day, Week, Variation, Minimum needed), the date and optionally a scenario.

The week (Monday to Sunday) containing the chosen date. Each cell is one hour: the number is the trips, the colour the longest wait (green = none, yellow, red = long). “Variation” view

The planned day uses exact times. In reality the truck comes earlier or later and unloading takes different amounts of time. The variation therefore calculates the chosen day many times with random deviations:

  • arrival ± the delivery's variation (planned time most frequent),
  • unloading time at the gate randomly between from and to,
  • passenger trips in lifts according to the base load, at different moments each time.

Scenarios

A scenario is a copy of the current state with changes, for example: “Linen arrives at 7:30 instead of 8:00”, “Lift West under maintenance”, “one more AGV”, “Fire door B closed”. The real data stays unchanged until you explicitly apply a scenario.

Creating and editing

Add scenario → name and description. In the editor you only change what should be different. Changed fields are marked; the list shows the number of differences.

SectionWhat can be changed

Transport typesNumber and speed. A changed number applies all day in the scenario, instead of the shifts.

Block path segmentsBlock named path segments, e.g. a door closed for construction. Only named segments appear here; you give names in the map editor.

Viewing, comparing, applying

  • Compare: opens the analysis with this scenario. The small grey numbers show the current state for comparison, with a conclusion above, e.g. “In the scenario there is 1 h 20 min less waiting in total. Late trips: 5 → 1”.
  • Timeline: the scenario can also be chosen at the top of the map timeline and in the Week, Variation and Minimum needed views.
  • Apply: writes the changed deliveries into the current state, after confirmation. Changes to lifts, transport types, ramps and blocks are not applied; enter those yourself in master data or on the map if needed.

Step-by-step guides

Truck delivery through three gates into the store and to the ward

  1. Map → floor with the service yard → Edit.
  2. Draw paths: path from the dock through goods-in into the store and on to the lift. Right-click ends the line.
  3. Add point at the dock, type Gate / dock (truck), name “Dock”, At most at the same time 3, unloading per pallet e.g. 2 to 4 minutes.
  4. Place the point “Store” (start/destination) and the lift (lift/stairs) on the path. On the ward floor place the same lift, draw the corridor and add the point “B25”.
  5. Deliveries: “At 08:00, 10 pallets from Dock to Store, then stays there / truck leaves”.
  6. Distribution: “At 09:00, 2 roll containers from Store to B25, then return empty”.
  7. Analysis → Day: does the truck wait at the gate? Does the distribution wait at the lift?

Bed exchange: soiled there, clean back

  1. Add points “Ward B25” and “Bed reprocessing”, check the cart type “Bed” (space needed 2).
  2. Delivery: direction Internal, start ward B25, destination bed reprocessing, load 1 bed.
  3. Return trip: return loaded, return to ward B25. The clean bed goes back.
  4. In the one-line entry this is “then: return loaded (e.g. clean bed)”.

How many transport service staff do I need?

  1. Enter all deliveries of a typical day, check master data (speed, loading and unloading times, lifts).
  2. Analysis → Minimum needed → What? “Transport service”, maximum wait e.g. 10 minutes → Calculate.
  3. Result e.g. “4 vehicles or staff are enough”, i.e. 4 people on duty at the same time.
  4. Repeat “with variation” to cover fluctuations.
  5. In the “Day” view look at the utilisation to see when these 4 are needed, and build shifts from it (master data → transport type → shifts).

What happens if a lift fails?

  1. Scenarios → Add scenario, name “Lift West under maintenance”.
  2. Under lifts and stairs: tick Lift West out of service.
  3. Compare: how much longer is the waiting, which deliveries no longer have a route?
  4. Shift times in the scenario until it works. If you like the result, write the deliveries into the current state with Apply.

An AGV must not use certain corridors

See Path segments: click the path, “Blocked for: AGV”, tick “whole path”. If an AGV must not use a particular lift, tick all other transport types under “Only for these transport types” at the lift. If it should only use one particular lift, enter it as a via point.
